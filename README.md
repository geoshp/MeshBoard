# MeshBoard

Веб-дашборд для companion-ноды [MeshCore](https://meshcore.io): каналы, личные сообщения, опрос
своих репитеров, графики, карта и трассировки. Интерфейс на русском, тёмная тема, рассчитан
в первую очередь на телефон (в том числе складной).

- **Backend:** Python 3.12, asyncio, FastAPI, WebSocket, SQLite (WAL), библиотека
  [`meshcore`](https://pypi.org/project/meshcore/) 2.3.19.
- **Frontend:** Vite + React + TypeScript, ECharts, Leaflet. Внешние CDN не используются,
  из сети грузятся только тайлы карты.
- **Запуск:** docker compose. Подключение к ноде по USB/serial или по TCP (WiFi). BLE не поддерживается.

Этапы работ и ограничения библиотеки описаны в [PLAN.md](PLAN.md).

## Возможности

| Раздел | Что есть |
|---|---|
| Каналы | Список каналов ноды, лента в реальном времени, отправка, у входящих SNR, RSSI и путь (имена репитеров) |
| Личные | Диалоги и контакты, отправка с ожиданием ACK и повторами, статус доставки и RTT, счётчики непрочитанного |
| Репитеры | Флаг «мой репитер», опрос по расписанию с настраиваемым интервалом: статус, телеметрия (LPP), соседи. Только чтение |
| Графики | Батарея, радио (шум/SNR), аптайм, airtime, пакеты, SNR/RSSI принятых сообщений, сообщения по часам, активность контактов. Периоды 1 ч … 30 дн, своя нода или любой репитер |
| Карта | Узлы с GPS, подписи, цвет по давности активности, линии маршрутов контактов, путей сообщений, трассировок, соседей репитеров. Запуск trace до выбранного узла |
| Нода | Состояние подключения, параметры радио, текущие метрики |
| Хранение | Сообщения, метрики, опросы репитеров и трассировки в SQLite, срок хранения задаётся отдельно для сообщений и метрик |

## Быстрый старт без железа (эмулятор)

```bash
cp .env.example .env
# обязательно задайте пароль входа (не короче 8 символов):
sed -i 's/^MESHBOARD_PASSWORD=.*/MESHBOARD_PASSWORD=придумайте-пароль/' .env

docker compose -f docker-compose.yml -f docker-compose.mock.yml up -d --build
```

Откройте http://127.0.0.1:8080 и войдите с паролем из `.env`.

Эмулятор (`MESHCORE_MOCK=1`) — это TCP-сервер, который говорит бинарным companion-протоколом
MeshCore. Backend подключается к нему тем же `MeshCore.create_tcp()`, что и к реальной ноде,
поэтому разбор событий идёт через настоящий парсер библиотеки. В эмуляторе есть 12 контактов
(5 репитеров, 6 клиентов, комната), 3 канала, входящие сообщения с путями, ACK, логин в репитеры,
статус, телеметрия, соседи и trace. При первом запуске на пустой базе он создаёт синтетическую
историю за 48 часов, чтобы графики не были пустыми. `MESHCORE_MOCK_SPEED` ускоряет поток событий.

## Подключение по USB (serial)

1. Узнайте устройство и группу-владельца:
   ```bash
   ls -l /dev/serial/by-id/      # стабильное имя, например usb-Heltec...-if00
   stat -c %g /dev/ttyUSB0       # gid группы (обычно 20 = dialout)
   ```
2. В `.env`:
   ```ini
   MESHBOARD_PASSWORD=...
   MESHCORE_SERIAL_DEVICE=/dev/serial/by-id/usb-...-if00   # путь на хосте
   SERIAL_GID=20
   MESHCORE_SERIAL_BAUDRATE=115200
   ```
3. Запуск:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.serial.yml up -d --build
   ```
   Override пробрасывает устройство в контейнер как `/dev/ttyMESH` и сам выставляет
   `MESHCORE_CONNECTION=serial`. На ноде должна стоять прошивка **companion USB/serial**.

## Подключение по WiFi (TCP)

Нужна нода с прошивкой **companion WiFi**, которая слушает TCP-порт (обычно 5000).

```ini
MESHBOARD_PASSWORD=...
MESHCORE_CONNECTION=tcp
MESHCORE_TCP_HOST=192.168.1.50
MESHCORE_TCP_PORT=5000
```

```bash
docker compose up -d --build
```

## Пароли через Docker secrets

Вместо переменных окружения можно держать пароли в файлах:

```bash
mkdir -p secrets
printf '%s' 'пароль-входа' > secrets/meshboard_password.txt
cat > secrets/repeater_passwords.txt <<'EOF'
# префикс_ключа_или_имя=пароль
c3295e=пароль-репитера-1
RPT Север=пароль-репитера-2
EOF
chmod 600 secrets/*.txt
docker compose -f docker-compose.yml -f docker-compose.secrets.yml up -d --build
```

Override-файлы можно комбинировать, например
`-f docker-compose.yml -f docker-compose.serial.yml -f docker-compose.secrets.yml`.
Любую переменную-секрет можно задать и как `ИМЯ_FILE=/путь/к/файлу`.

## Доступ с телефона

По умолчанию порт опубликован только на `127.0.0.1` (в дашборде есть личные сообщения).
Есть три варианта:

- **SSH-туннель** (самый безопасный): `ssh -L 8080:127.0.0.1:8080 user@server`, затем открыть
  http://127.0.0.1:8080 на устройстве, где поднят туннель.
- **Reverse proxy с HTTPS** (Caddy, nginx, Traefik) перед контейнером. Задайте
  `MESHBOARD_COOKIE_SECURE=1` и проксируйте WebSocket `/api/ws`.
- **Локальная сеть**: `MESHBOARD_BIND=0.0.0.0`. Трафик пойдёт по HTTP без шифрования, вариант
  подходит только для доверенной сети.

## Настройки

Все переменные с комментариями перечислены в [.env.example](.env.example). Основные:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `MESHBOARD_PASSWORD` | — (обязательно) | Пароль входа, минимум 8 символов |
| `MESHBOARD_SECRET_KEY` | случайный | Ключ подписи сессий. Если не задан, сессии сбрасываются при перезапуске |
| `MESHCORE_CONNECTION` | `tcp` | `serial` или `tcp` |
| `MESHCORE_MOCK` | `0` | `1` включает эмулятор ноды |
| `MESHBOARD_RETENTION_MESSAGES_DAYS` | `90` | Срок хранения сообщений и трассировок |
| `MESHBOARD_RETENTION_METRICS_DAYS` | `30` | Срок хранения метрик, активности и опросов репитеров |
| `MESHBOARD_SELF_POLL_SEC` | `60` | Период опроса метрик своей ноды |
| `MESHBOARD_REPEATER_POLL_MIN` | `15` | Интервал опроса репитеров по умолчанию (меняется в UI) |
| `MESHBOARD_OWN_REPEATERS` | — | Начальный список своих репитеров (префиксы ключей). Дальше флаг ставится в UI |
| `MESHBOARD_REPEATER_PASSWORDS` | — | Строки `префикс_или_имя=пароль` (лучше через `_FILE`) |
| `MESHBOARD_REPEATER_DEFAULT_PASSWORD` | не задан | Пароль для остальных репитеров. Пустая строка означает гостевой вход, если переменная не задана, логина нет |
| `MESHBOARD_TILE_URL` | OSM | Шаблон URL тайлов карты |

Данные лежат в volume `meshboard-data` (`/data/meshboard.db`). Резервная копия:
`docker compose exec meshboard python -c "import sqlite3; sqlite3.connect('/data/meshboard.db').backup(sqlite3.connect('/data/backup.db'))"`.

## Разработка без Docker

```bash
# backend
cd backend
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
MESHCORE_MOCK=1 MESHBOARD_PASSWORD=devpassword python -m app.main   # http://127.0.0.1:8080

# frontend (во втором терминале): dev-сервер с прокси на backend
cd frontend
npm ci
npm run dev        # http://127.0.0.1:5173
npm run build      # сборка в frontend/dist, backend отдаёт её сам
```

## Тесты

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -q
```

Что покрыто:

- `test_parse.py` — разбор payload событий в записи БД (каналы, ЛС, пути, trace, метрики, LPP);
- `test_db.py` — хранилище: дедупликация, непрочитанные, метрики и счётчики, ретеншн, WAL;
- `test_config_security.py` — конфигурация и `_FILE`, пароли репитеров, сессии, лимит попыток, маскировка секретов;
- `test_emulator_lib.py` — настоящая библиотека `meshcore` против эмулятора: сопоставление пути и
  RSSI с сообщением канала, ACK, логин, статус, телеметрия, соседи, trace, статистика;
- `test_api.py` — приложение целиком на эмуляторе: авторизация, CSRF, отсутствие секретов в ответах,
  лента и непрочитанные, отправка в канал и ЛС с доставкой, опрос репитера, trace и карта, графики,
  переподключение.

## Безопасность

- Без `MESHBOARD_PASSWORD` приложение не стартует. Сессия хранится в cookie, подписанной HMAC
  (`HttpOnly`, `SameSite=Strict`). Неудачные попытки входа ограничены: 10 за 5 минут с одного адреса.
- Запросы, меняющие состояние, и WebSocket проверяют `Origin`. Ответы отдаются с CSP,
  `X-Frame-Options: DENY` и `no-store` для API.
- Пароли и ключи не хранятся в репозитории и не попадают в логи. Фильтр маскирует их значения,
  включая hex-вид. Логгер `meshcore` не опускается ниже INFO, потому что на DEBUG библиотека
  печатает сырые кадры с паролем логина. Тексты сообщений в лог не пишутся.
- Секреты каналов не сохраняются в БД и не отдаются фронтенду.
- Контейнер работает без root, с read-only файловой системой, `cap_drop: ALL` и `no-new-privileges`.
- Административных действий над репитерами (перезагрузка, настройки, CLI) в v1 нет, только чтение.

## Что проверить на реальной ноде

Всё проверено на эмуляторе, который повторяет форматы кадров из `meshcore/reader.py`. На железе
стоит отдельно проверить:

1. Подключение по USB и по TCP, переподключение после отключения кабеля или WiFi.
2. Путь и RSSI у сообщений каналов. Для этого прошивка должна присылать `LOG_RX_DATA`. Если её
   нет, будет показано только число хопов.
3. ACK и RTT у личных сообщений, повторы при потере ACK.
4. Логин в свои репитеры с паролями из окружения, статус, телеметрия и соседи (зависит от версии
   прошивки репитера и прав гостя/админа).
5. Trace до репитера по известному пути и до прямого соседа.
6. `get_stats_*` на вашей версии прошивки. На старых прошивках графики airtime и пакетов своей ноды
   будут пустыми.
